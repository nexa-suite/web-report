# Estructura del informe

La carpeta `report/` sigue el índice del informe de Aplicaciones Web. Los capítulos son carpetas numeradas y las secciones que pueden crecer se mantienen como subcarpetas con su archivo Markdown principal dentro.

## Capítulos

- `00-front-matter/`: carátula, versiones, colaboración, contenido y Student Outcome.
- `01-introduction/`: Startup Profile, Solution Profile, Lean UX y segmentos objetivo.
- `02-requirements-elicitation-and-analysis/`: competidores, entrevistas, needfinding, Big Picture EventStorming y Ubiquitous Language.
- `03-requirements-specification/`: User Stories, Impact Mapping y Product Backlog.
- `04-product-design/`: style guidelines, information architecture, landing page, aplicaciones web, arquitectura, diseño OO y base de datos.
- `05-product-implementation-validation-deployment/`: configuración, sprints, validación y video About-the-Product.
- `90-conclusions/`, `91-video-about-the-team/`, `92-bibliography/` y `93-annexes/`: contenido final del informe.

## Regla de organización

Cuando una sección tiene subsecciones o artefactos que crecerán durante el ciclo, se crea una carpeta numerada para esa sección y se coloca dentro el Markdown correspondiente. Esto permite ampliar el informe sin mezclar capítulos ni perder trazabilidad en Git.
